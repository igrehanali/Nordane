# Decisions

A running log of the choices made building this portal, and the reasoning. Where
something in the original brief was cut down or traded away, it is recorded here
rather than quietly dropped.

Dates are the date the decision was taken.

## 2026-09-27 — Foundations (slice 0)

### Money is integer minor units, enforced by the type system
All amounts are `integer` columns named `*_minor` and a branded `Money` type in
[`src/lib/money.ts`](src/lib/money.ts). A raw `number` cannot reach an amount
parameter without passing `asMoney` or `parseMoney`, both of which validate.
Rounding is half-away-from-zero, applied once per derived amount. An ESLint rule
bans `parseFloat` outright.

**Why:** an invoice that is one cent out is a support call, and floating point
arithmetic guarantees you will eventually get one. `0.1 + 0.2 !== 0.3`.

### Postgres driver: `pg`, not `@neondatabase/serverless`
One driver for local dev, CI, migrations, the seed script and production.

**Why:** the Neon serverless driver is faster to cold-start over HTTP, but it
would mean two code paths (HTTP for queries, TCP for migrations and seeding) and
divergent behaviour between local and deployed. Neon's pooled endpoint works with
`pg` today; if cold starts become a problem this is a one-file swap.

### Tenancy is enforced in the data access layer, not Postgres RLS
Every customer-scoped query lives behind a module where `companyId` is a required
argument. There is no exported query that can omit it.

**Why:** real RLS policies need a per-request database role and `SET LOCAL`
session variables on a pooled connection — roughly a day of work plus a
permanent debugging tax. One application, one trust boundary, enforced at the
only place queries are written. The brief asked for tenancy enforced in queries,
which is exactly this.

### shadcn/ui components are vendored by hand, not generated by the CLI
The primitives in `src/components/ui` are written in the shadcn idiom (Radix +
`cva` + `cn`) but committed directly.

**Why:** avoids an interactive CLI and a `components.json` dependency, and only
the primitives actually used get written. Same pattern, same ownership model,
less machinery.

### Tailwind v4 with semantic tokens only
Colours are defined once as CSS custom properties in
[`src/app/globals.css`](src/app/globals.css) and exposed through `@theme inline`.
No component references a raw colour. Light and dark are the same token names
with different values.

**Why:** adding a theme, or changing the brand, must never mean touching a
component. Contrast pairs are picked to clear WCAG AA in both themes.

### Sessions are JWT, not database-backed
Auth.js v5 with the credentials provider and JWT session strategy — no adapter,
no `sessions` or `accounts` tables.

**Why:** credentials-only auth gains nothing from database sessions, and it saves
four tables and a round trip per request. Trade-off: revoking a session before it
expires is not instant. Acceptable here; noted in case it ever isn't.

### Email: console transport by default
Order confirmations print to the server log. A Resend adapter sits behind
`EMAIL_TRANSPORT=resend`.

**Why:** the brief allows it, and a real mail provider adds a signup, a domain and
DNS records before anything is demonstrable.

## Deliberately not built

Recorded so the gaps read as decisions rather than oversights.

| Not built | Instead | Why |
| --- | --- | --- |
| Real sales-tax jurisdiction logic | One configurable rate per branch, plus a per-customer exemption flag | Nexus and product-level taxability is weeks of work and no prospect will test it in a demo |
| Product image pipeline / uploads | Deterministic SVG placeholders per category, showing the SKU | 300 products that look intentional beats 12 with real photographs |
| Stripe payment link | Nothing | Trade customers pay on 30-day terms. A card button at checkout undermines the credit-account story this portal exists to tell |
| Real manufacturer brand names | Fictional brands (BW Pro, Kessler, ThermaCore, Nordane, Volturi) | Real trademarks on a public portfolio site is an avoidable problem |
| Postgres row-level security policies | Data access layer enforcement (above) | See above |
| Stored PDF files | Invoices and statements rendered on demand | No object storage to configure, nothing to keep in sync, and the PDF always matches the current data |
